# رادار الخيارات الأمريكية — Options Radar AR

لوحة عربية متجاوبة للويب وAndroid لمراقبة سلسلة خيارات الأسهم وصناديق ETF الأمريكية.

## ما الذي يعمل؟
- بحث عن رموز مثل SPY وQQQ وNVDA وMU وTSLA وMETA وAMD وAVGO.
- استدعاء سلسلة الخيارات من endpoint عام لـ Yahoo Finance عبر خادم Express لتجنب CORS في المتصفح.
- عرض السعر الأخير وBid/Ask والحجم وOpen Interest وIV ونسبة Volume/OI وقيمة تداول تقريبية.
- ماسح أولي يرشح الحجم العالي مقارنةً بـ Open Interest.
- رسم شموع يومية وحجم تداول باستخدام مكتبة Lightweight Charts مفتوحة المصدر.
- مؤشرات EMA 9 وEMA 21 وRSI 14.
- حسابات Black–Scholes تقريبية لـ Delta/Gamma/Theta/Vega، والحركة المتوقعة، ومؤشر GEX افتراضي مع توضيح افتراضاته.
- وضع عرض تجريبي لتجربة الواجهة عندما لا يعمل المصدر المجاني.
- واجهة RTL عربية ومناسبة لشاشة الهاتف.

## حدود مهمة جدًا
- مصدر Yahoo Finance هنا غير رسمي، وقد يغيّر الوصول أو يحدّه أو يحجب الطلبات. توقيت البيانات وتوفر السلسلة ليسا مضمونين.
- لا يوفّر هذا المشروع تدفق OPRA مباشرًا مضمونًا، ولا يصنّف الصفقات إلى sweeps أو block trades، ولا يملك GEX موثوقًا إذا لم تكن Greeks اللازمة متاحة. لا يختلق هذه المؤشرات.
- قيمة التداول الظاهرة تقدير حسابي (آخر سعر × الحجم × 100)، وليست premium flow مصنفًا حسب جهة الشراء/البيع.
- وضع العرض التجريبي يستخدم أرقامًا اصطناعية؛ لا تستخدمها في قرارات تداول.
- لا توجد أوامر شراء/بيع أو ربط بحساب وسيط.

## التشغيل محليًا
يتطلب Node.js 20 أو أحدث.

```bash
npm install
npm run dev
```

- واجهة Vite: `http://localhost:5173`
- خادم البيانات: `http://localhost:8787/api/health`

```bash
NODE_ENV=production npm start
```

## Android
تم تجهيز إعداد Capacitor وسير عمل GitHub Actions لبناء APK تجريبي. إذا لم يكن خادم البيانات منشورًا، يعرض التطبيق الأصلي وضع العرض التجريبي بوضوح بدل اختلاق بيانات حقيقية. لربط البيانات الحقيقية، انشر خادم Express على HTTPS ثم عرّف `VITE_API_BASE_URL` بعنوان الخادم قبل البناء. لا تضع مفاتيح API في الواجهة.

على جهاز به Android Studio:

```bash
npm install
npm run android:init
npm run android:sync
npm run android:open
```

ثم ابنِ APK من Android Studio. أو ارفع المشروع إلى مستودع GitHub وفَعّل Actions وشغّل سير العمل `Build Android APK`؛ سيظهر `app-debug.apk` ضمن Artifacts بعد نجاح البناء. هذا ملف Debug للاختبار، وليس إصدارًا موقّعًا للنشر التجاري. يمكن أيضًا استضافة الواجهة على HTTPS وتثبيتها كتطبيق ويب إذا كان خادم البيانات منشورًا على عنوان متاح.

## النشر
- لا يكفي GitHub Pages لتشغيل خادم Express. استضف المشروع على خدمة تدعم Node.js (مثل Render أو Railway أو Fly.io) أو افصل الواجهة عن الخادم.
- لا تضف أسرارًا أو مفاتيح API إلى GitHub. إذا أضفت مزود بيانات لاحقًا، خزّن المفتاح في متغيرات بيئة الخادم.
- افحص شروط ترخيص مزود البيانات قبل إعادة توزيع البيانات أو عرضها لمستخدمين آخرين.


## مصادر مفتوحة مدمجة/مرجعية
راجع `LICENSES-AND-SOURCES.md` لتفاصيل مكتبات الرسم والتحليل ومصادر الأبحاث المفتوحة وحدود الترخيص.

## محرك الأهداف وفحص السيولة (إضافة)
- يتيح اختيار عقد من السلسلة وتحديد هدف سعر السهم وتغيير افتراضي في IV، ثم يعرض سعرًا نظريًا للعقد والعائد النظري ونقطة التعادل.
- مستويات Pivot وATR ونطاق 20 جلسة تُشتق من شموع تاريخية متاحة. هذه سيناريوهات وليست تنبؤات مؤكدة.
- فحص السيولة يقيس السبريد ونسبة الحجم إلى OI. لا توجد خوارزمية يمكنها إثبات أن المشتري مؤسسة من هذه البيانات وحدها.
- لوحة Dark Pool تتضمن موصلًا اختياريًا إلى FINRA Developer API لملخص ATS الأسبوعي المجمع عند توفير `FINRA_API_TOKEN`. هذا ليس تدفقًا لحظيًا ولا يكشف جهة الشراء أو هوية المؤسسة. لا يزال شريط الصفقات الفردية اللحظي يحتاج مزودًا مرخصًا.

## إعداد مصدر بيانات لخادم Android
ملف APK المولّد من GitHub Actions سيحتاج إلى backend عام إذا أردت بيانات السوق داخل الهاتف. انشر `server/` على خدمة تدعم Node.js/HTTPS، ثم أضف `VITE_API_BASE_URL` في GitHub Secrets مع عنوان الخادم الكامل (مثال: `https://your-api.example.com`). وإذا أردت الملخص الأسبوعي لـ FINRA، أضف `FINRA_API_TOKEN` إلى متغيرات بيئة الخادم فقط. لا تضع هذا الرمز في واجهة الويب أو GitHub كملف. إذا تركت `VITE_API_BASE_URL` فارغًا، فلن يكون هناك backend متاح داخل APK؛ ستعمل الواجهة فقط ويمكن استخدام العرض التجريبي بوضوح.
